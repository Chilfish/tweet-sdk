# Audit — 2026-11-19

Scope: `@chilfish/tweet` at commit `f134306` (Phase 0 + CLI). Reviewed before wiring
the package into the web app.

Methods:

- static review of `src/` (module graph, dependency directions, dead code)
- `bun run typecheck` / `lint:check` / `test:coverage` / `build` / `verify:package`
- real upstream run with a cookie from `.env` (`TWEET_KEYS`), covering
  `get` / `replies` / `search` / `user` / `space`
- dependency and bundle inspection

Counts at the end of the audit: 117 offline tests + 5 live tests, line coverage ~39%.

## Verdict

The core is structurally sound and the real endpoints work, but the first cut had
three release blockers (request amplification, no timeout, oversized install) and
noticeable dead code. All blockers are fixed in this audit.

**Status: ready for `0.1.0` after the English-content pass and a manual npm
Trusted Publisher setup.** Not yet ready for a React package (Phase 3 is not built).

## Architecture

```
src/index.ts ─┐
src/node.ts  ─┼─> client / pool / parse ─> services ─> requests ─> types
src/cli.ts   ─┘
```

- Transport is an injected `HttpClient` (fetch by default). Nowhere in `src/lib`
  is `node:*` imported at runtime, so the neutral build holds.
- Request builders return plain `HttpRequest` descriptors; auth, retries and the
  transaction-id header live in `FetcherService`.
- Parsing/enrichment is pure and IO-free; `attachSpaceDetails` takes the fetch
  function as an argument.
- `EnrichedTweet` is the single contract between core and UI.

## Findings and fixes

| # | Severity | Finding | Resolution |
|---|---|---|---|
| 1 | High | A new `ClientTransaction` was created per API call: 1–5 shell requests plus ~1 MB HTML parsing each time. | `transaction.ts` now caches per cookie for 10 min, de-duplicates concurrent initialisation, and refetches once if id generation fails. Real integration run dropped from ~9.3 s to ~4.6 s for 5 calls. |
| 2 | High | Guest sessions re-activated a token on every request (two extra requests each). | `AuthService` caches the guest credential per fetcher for 10 min. |
| 3 | High | No default request timeout: `fetch` can hang forever. | Default 30 s in `RettiwtConfig`; `timeout: 0` disables it (long media uploads). |
| 4 | Medium | Body-level errors returned with HTTP 200 (`errors` array) were neither classified nor retryable. | `createBodyError` maps code 32/89 → `AuthError(401)`, 88 → `RateLimitError(429)`, so the pool rotates keys. |
| 5 | Medium | `undici` (2.08 MB) was a hard dependency only used for the optional proxy dispatcher. | Moved to an **optional peer dependency**; `createProxyFetch` imports it lazily and fails with an actionable message if missing. |
| 6 | Medium | Dead code: the unused `Rettiwt` facade, five services reachable only from it, and five unreferenced raw response types. | Deleted; `TwitterAPIClient`, `TweetEnrichmentService` and `FetcherService` remain. |
| 7 | Medium | Coverage was 26% — critical transport paths untested. | Added tests for `FetcherService` (headers, timeout, error mapping, 404 retry, middleware), `AuthService` (cookie rotation, guest cache), transaction caching/dedupe, `TwitterClient` and `parseSearchTimeline`. Coverage is now ~39%. |
| 8 | Low | `createNodeClient` encoded cookies with raw `btoa`, which throws on non-Latin1 input. | Uses `encodeBase64` consistently. |
| 9 | Low | `LogService.enabled` is process-global and set by the last constructed config. | Accepted: it only gates debug logging. Documented here. |
| 10 | Low | SOCKS proxies are not supported by the fetch transport. | `createProxyFetch` rejects non-`http(s)` schemes with a clear error. |
| 11 | Low | The ported parser uses `any` at upstream boundaries. | Accepted debt: narrowing happens in the mappers/fixtures; no runtime risk identified. |

## Recommended before web integration

1. Build the `./react` surface (Phase 3): `TweetProvider` (link/media/slots) and
   pure display components; keep prompts, translation, AI and screenshot logic in
   the app via slots.
2. Add a Workers smoke test (miniflare) for the transaction document path.
3. Add a fixture-shape snapshot probe to detect upstream contract drift early
   (postmortem 013/014 prevention).
4. Raise coverage of the request-builder layer (descriptor snapshots) to catch
   missing feature flags when X changes GraphQL requirements.
