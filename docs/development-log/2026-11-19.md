# 2026-11-19

## Done

- Phase 0 package bootstrap: multi-entry skeleton for `@chilfish/tweet` (`.` core, `./node`), ported into `src/lib/` with the viewer's `packages/rettiwt-api` as the baseline.
- Removed axios from the transport layer: added `HttpClient` / `HttpRequest` / `HttpResponse` plus a fetch implementation; `requests/*` are now neutral descriptors.
- Removed Node dependencies from auth: `Buffer` → `atob` / `btoa`, `cookiejar` → built-in cookie parsing, `node:querystring` → `encodeQueryParams` / `stringifyFormData`.
- Consolidated platform capabilities into `src/node/`: proxy dispatcher (undici `ProxyAgent`), `readMediaFile`, `createNodeClient` (reads `TWEET_KEYS` / `http_proxy`).
- Replaced the error model with the `TwitterApiError` family; `TwitterError` / `ErrorService` removed, `errorHandler` kept as an optional hook.
- `RettiwtPool` now has SmartPool as its only implementation, with an injectable logger added (`pool.rotate` / `pool.exhaust`).
- Parser layer moved into core (migrated from anonTweet's react-tweet utils): `enrichTweet`, entities, poll, space, article, organizeTweets, jetfuel.
- Unified field naming: `id` / `quotedTweet` / `quotedTweetId` / `retweetedOriginalId` / `isInlineMedia`.
- Tests: ported the Space / poll / card / transaction-id fixtures and added contract tests for HTTP, Pool, enrich, and the export surface (63 tests).
- Docs: README, api, package-contract, architecture, build-and-release, dependencies, security, getting-started, usage, and CHANGELOG all synced.

## Decisions

- Do not export the old `Rettiwt` facade: it is tied to `RettiwtConfig` and the axios shape, so keeping it would drag that coupling back into the public surface.
- `buildXShellHeaders` still accepts a base64 apiKey; `TidProvider` internally receives an already-decoded cookie, so core does not depend on `AuthService`.
- `./react` and `package.json#exports["./react"]` are deferred to Phase 3, to avoid declaring build outputs that do not exist.
- `undici` may only be loaded lazily inside `./node`; core uses `fetch` by default, so Workers / Deno / Bun / browsers need zero changes.
- SOCKS proxies are not supported for now: the fetch transport's `ProxyAgent` only accepts `http(s)://`, and `createProxyFetch` surfaces an explicit error.

## Addendum: pre-integration audit (same day)

- Ran the real upstream suite from `.env` (`TWEET_KEYS` + a known tweet): `get`, `replies`, `search`, `user`, `space` all pass.
- Fixed request amplification: the transaction document/`ClientTransaction` is cached per session cookie for 10 minutes, concurrent init is de-duplicated, and a stale shell triggers one refetch. Five live calls dropped from ~9.3 s to ~4.6 s.
- Guest sessions now cache their credential per fetcher instead of re-activating a token per request.
- Added a 30 s default request timeout (`timeout: 0` disables it for long uploads).
- Classified body-level errors: code 32/89 → auth, 88 → rate limit, so the pool rotates keys.
- `undici` moved to an optional peer (lazy import with an actionable error); `dependencies` are now just `linkedom` and `x-client-transaction-id`.
- Removed dead code: unused `Rettiwt` facade, five services only reachable from it, five unreferenced raw types, and an unused helper barrel.
- Added `FetcherService` / `AuthService` / transaction-cache / `TwitterClient` / date tests; coverage rose from ~26% to ~39% (117 offline tests + 5 live tests).
- Prepared `0.1.0`: version bump and CHANGELOG section. Publishing still requires npm Trusted Publisher setup and pushing the tag.
- Full findings live in [audit-2026-11-19.md](../engineering/audit-2026-11-19.md).
